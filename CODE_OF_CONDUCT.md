# Código de conducta

## Propósito

Este código de conducta define las normas básicas de respeto y colaboración para el desarrollo de este proyecto.

El objetivo es mantener un ambiente de trabajo ordenado, responsable y colaborativo durante el uso del repositorio, la creación de ramas, commits, pull requests y documentación.

## Alcance

Este código aplica a todas las personas que participen en el proyecto, incluyendo integrantes del equipo, revisores y colaboradores.

Aplica en:

- Repositorio de GitHub.
- Issues.
- Pull requests.
- Comentarios de revisión.
- Documentación del proyecto.
- Comunicación relacionada con el desarrollo.

## Comportamiento esperado

Se espera que los integrantes del proyecto:

- Mantengan una comunicación respetuosa.
- Trabajen de forma colaborativa.
- Usen comentarios claros y constructivos.
- Respeten el trabajo realizado por otros integrantes.
- Revisen los cambios antes de integrarlos.
- Cumplan las convenciones definidas en la documentación.
- Eviten subir información sensible al repositorio.
- Mantengan una actitud responsable frente a errores o problemas.

## Comportamiento no aceptado

No se acepta:

- Uso de lenguaje ofensivo o discriminatorio.
- Comentarios agresivos o burlas hacia otros integrantes.
- Eliminar o modificar trabajo de otra persona sin acuerdo previo.
- Subir claves, contraseñas o datos sensibles.
- Ignorar las normas de ramas, commits y pull requests.
- Realizar cambios directos en `main` sin revisión.
- Ocultar errores que afecten el funcionamiento del proyecto.

## Resolución de conflictos

Si existe un problema o desacuerdo, se recomienda:

1. Conversar con respeto entre los integrantes.
2. Revisar la documentación del proyecto.
3. Analizar el historial de commits y pull requests.
4. Llegar a un acuerdo antes de integrar cambios.
5. Solicitar apoyo del docente si el conflicto no puede resolverse.

## Buenas prácticas de colaboración

Para mantener una buena organización del proyecto:

- Cada cambio debe realizarse en una rama correspondiente.
- Los commits deben tener mensajes claros.
- Los pull requests deben explicar el cambio realizado.
- Las revisiones deben enfocarse en mejorar el proyecto.
- La documentación debe mantenerse actualizada.
- Las decisiones importantes deben quedar registradas.

## Compromiso

Los integrantes se comprometen a respetar este código de conducta y a colaborar de manera responsable para cumplir los objetivos del proyecto.

El cumplimiento de estas normas ayuda a mantener la trazabilidad, la calidad del código y una buena dinámica de trabajo en equipo.
